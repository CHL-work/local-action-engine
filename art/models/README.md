# Generated demo models

The committed FBX files under `unity/Assets/Brainwash/Resources/Models` were generated by these Python recipes for the existing engineering demo. Unity builds and releases use those committed outputs; Blender is not required to build or play the demo.

`bwkit.py` constructs signed-distance-field forms and low-poly meshes, generates palette UVs and bone weights, and exports FBX. `creatures.py` and `recipes_*.py` define shapes. `build_models.py` writes FBX, `palette.json`, and `models.json` into Unity's Resources directory. Unity's `ModelImport`, `ModelLibrary`, and `CreatureAnimator` handle import, coloring, and procedural motion.

Optional regeneration needs Blender's Python API (`bpy`), numpy, scikit-image, and Pillow. The source project used Blender 5.x / Python 3.13; regeneration on a different toolchain has not been checked by this extraction.

```powershell
python art/models/build_models.py goblin imp
python art/models/build_models.py goblin --preview .local/model-previews --no-fbx
```

Run these only in a separately prepared art environment. The first command overwrites the selected generated model outputs. The second renders previews; the script still updates its palette/model metadata. Review regenerated files before committing.

Models use metres and Blender Z-up, face -Y, and are imported into Unity with axis conversion. `CreatureAnimator` adjusts the resulting facing convention and animates named bones directly. Shared palette tint cells let actors reuse a mesh in different colors. Missing models fall back to primitive geometry, but the full demo acceptance intentionally checks that generated gallery models load.

The recipes and their committed outputs were copied from the same source revision as the demo. Private art direction documents and unrelated artwork are excluded.
